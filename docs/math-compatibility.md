# 数式互換変換と診断

## 調査と方針

2026-09-29時点では、はてなが配信する `tex-chtml.js` はMathJax 4.1.2でした。
MathJaxの公式コマンド一覧と当該バンドルに `\llbracket` / `\rrbracket` の定義は
見当たりません。ブログ独自の設定やマクロ定義によって動作が変わる可能性はあります。
CLIはこの配信ファイルを実行時に取得せず、小さな既知ルール集合でオフライン変換します。

| 方法 | 利点 | 制約・採用方針 |
| --- | --- | --- |
| `\mathopen{[\![}` / `\mathclose{]\!]}` | 標準の角括弧と負の空白だけで二重括弧を近似できる | 開き・閉じの数式クラスを保持。通常形で採用し、見た目の差を警告する |
| Unicode `⟦` / `⟧` | 1文字で表せる | フォント、拡大区切りの扱いに依存するので自動置換しない |
| `\newcommand` を記事に挿入 | ソースの呼び出しを維持できる | 定義のスコープ・既存マクロとの衝突がある。自動挿入しない |
| ブログのMathJax設定・拡張を変更 | 使える記法を増やせる場合がある | はてな管理のローダーと競合し得る。CLIから変更しない |

`\left` / `\right` / `\middle` は直後に区切りトークンを要求します。
そこへ複合式 `\mathopen{…}` を挿入すると構文が壊れます。
`\big` 系列も区切り引数を取るため、当面は警告して元のコマンドを保持します。
拡大した二重括弧には、式の構造に応じて手動で
`\bigl[\!\bigl[ x \bigr]\!\bigr]` のように固定サイズを指定できます。
自動サイズの厳密な代替には括弧対応・入れ子・フォントを含む別の検証が必要です。

## 診断の契約

| コード | 内容 | warn | strict |
| --- | --- | --- | --- |
| MATH001 | 既知コマンドを置換（近似／公式移行先はメッセージで区別） | 変換して警告 | 全件を通知し出力・通信前に失敗 |
| MATH002 | 安全に置換できない文脈 | コマンドを保持して警告 | 全件を通知し出力・通信前に失敗 |

`strict` は「変換できなかった場合だけ」でなく**すべての互換診断**で停止します。
たとえ近似できても、自動投稿で見た目の変化を見落とさないためです。
利用者は警告を確認して `warn` で変換するか、原稿を手動修正できます。
通常の未閉じ数式エラーは従来どおり、どの互換モードでもエラーです。

診断は入力上の行・列を保持し、CLIでファイル名とfront matterの行数を加えます。
コード・本文・リンク・HTMLブロックは互換検査の対象にしません。
TeXの制御綴り単位で照合し、`\llbracketOther` や `\\llbracket` を誤置換しません。
コメントは検査せず、数式内にマクロ定義を検出した場合は当該数式の既知コマンドを変更しません。
既存の `[$ … $]` も検査・変換しますが、旧 `[tex:…]` はエスケープ規則が異なるため通知のみです。
旧形式の走査は既存パーサーが認識する最初の閉じ角括弧までです。

Python APIでは `convert_math(..., diagnostics=list)` で構造化診断を収集できます。
収集先がなければ `warn` モードでPythonのwarningを出します。
`strict` は収集先へ診断を格納してから `HatebloError` を送出します。

## 検出できないものと拡張

この機能はTeXパーサー／MathJaxの完全な検証器ではありません。
未知のマクロ、未知の環境、未対応パッケージ、括弧の対応、引数不足、
別数式でのマクロ定義、ユーザー独自のMathJax設定までは検証しません。
診断が0件でも、はてなでの表示成功を保証しません。

今後網羅的なエラー検出を追加するなら、別の `check` コマンドで、固定バージョン・
固定パッケージ設定のMathJaxをローカル実行する方式が適しています。
その場合も `noundefined` による未定義コマンドの表示を成功とみなさず、
MathJaxのエラー節点・診断を収集する必要があります。
ブログ固有の拡張との差は「想定設定との差」として報告し、投稿APIの成功とは分けて扱います。
現在のCLIにNode.jsやMathJaxの常用依存は追加していません。

## 検証記録

MathJax 4.1.2を一時環境にインストールし、`noundefined` を無効化して
`tex2mmlPromise` の結果の `merror` を検査しました。
元の `\llbracket x \rrbracket` はエラー、通常の近似式・下付き文字内の近似式・
上記の固定サイズ手動代替・`\mathbb` / `\mathscr` はエラーなしでした。
これは構文処理の確認であり、実ブログのフォントや画面上の見た目の確認ではありません。
